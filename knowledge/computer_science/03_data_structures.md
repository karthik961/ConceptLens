# Data structures and algorithmic tradeoffs

**Concept notes written for the ConceptLens starter demo.**

A hash table typically supports expected constant-time lookup by key under appropriate assumptions, but collisions, resizing, and adversarial inputs can affect performance. Binary search on a sorted array uses O(log n) comparisons but requires sorted data.

A stack follows last-in, first-out order; a queue follows first-in, first-out. A linked list can insert a node efficiently when the insertion position is already known, but locating an arbitrary element generally requires traversal.

Statements about time complexity should specify the operation and assumptions; there is no single data structure that is always fastest for all operations.
